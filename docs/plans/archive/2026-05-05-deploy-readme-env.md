# Archived Plan: 部署整理與文件化

> 狀態：已完成
>
> 歸檔原因：這份計畫的目標是把既有 Vue 3 + Vite 專案整理成可交付、可部署、可接手的正式版本。相關工作已完成，並實際落地成 `docs/README.md`、`docs/ARCHITECTURE.md`、`docs/DEVELOPMENT.md`、`docs/FEATURES.md`、`docs/TESTING.md`、`docs/CHANGELOG.md`、`AGENTS.md` 與 `.env.example`。

## User Story
身為接手專案的開發者，我希望看到一組完整且可執行的文件，讓我不用翻完整個程式碼庫就能理解：

1. 這個網站是做什麼的。
2. 目前技術棧與啟動方式是什麼。
3. 哪些頁面負責哪些使用情境。
4. 官方領養資料如何串接與 fallback。
5. 新功能應該怎麼寫、怎麼測、怎麼歸檔。

## Spec
### 文件目標
- 建立根目錄 `AGENTS.md`
- 建立 `docs/` 文件樹
- 清楚描述技術棧、架構、開發規範、功能、測試與更新歷史
- 保留 `docs/plans/archive/` 作為計畫歸檔區

### 內容要求
- 每份文件都不能只寫骨架或概述
- 必須說明會影響其他模組開發與整合的關鍵知識點
- 若目前沒有後端、DB 或 auth，文件必須明確寫出「不存在」，不能假裝有

### 完成定義
- 文件可直接拿來交接
- 新進開發者能照 README 與 AGENTS 啟動專案
- 設計、功能、測試、歸檔流程都有可查詢的官方文件

## Tasks
### 1. 建立 `AGENTS.md`
- 寫專案概述
- 列出常用指令
- 明定關鍵規則
- 連到 `docs/` 文件

### 2. 建立 `docs/README.md`
- 說明專案用途、技術棧、快速開始與指令
- 列出文件索引
- 補充部署時應注意的靜態資源與環境變數

### 3. 建立 `docs/ARCHITECTURE.md`
- 說明 MPA 啟動流程
- 說明目錄結構與每個檔案用途
- 列出 API 路由總覽
- 說明統一回應格式與資料正規化
- 明確標示目前沒有 auth / DB / 金流

### 4. 建立 `docs/DEVELOPMENT.md`
- 補開發規範、命名規則、模組系統
- 補環境變數表
- 補 JSDoc 規則與範例
- 補計畫歸檔流程

### 5. 建立 `docs/FEATURES.md`
- 列出首頁、領養、故事、自評與資料適配的行為
- 說明查詢參數、預設值、業務邏輯與錯誤情境

### 6. 建立 `docs/TESTING.md`
- 說明目前沒有正式測試檔
- 定義未來測試應該怎麼補
- 列出執行順序與常見陷阱

### 7. 建立 `docs/CHANGELOG.md`
- 記錄主要改版
- 記錄文件系統與 Vue 重構結果
